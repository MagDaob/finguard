# 银行、模型与插件接口准备规划

状态：接口准备已实现。修订日期：2026 年 10 月 27 日。实际入口、类型和限制见[扩展接口说明](extension-interfaces.md)。

本轮按用户要求重新收敛范围：只准备接口、配置结构和扩展契约，不新增真实银行或模型厂商的专用适配与联调。个人银行卡仍为银行领域的主要设计对象。

现有独立模拟银行和 DeepSeek 接入继续保留。本文记录本期范围和验收约定；此前银行报文调研仅作历史参考，不作为本期开发任务。

## 本期交付范围

| 工作线 | 准备内容 | 完成标志 |
|---|---|---|
| 银行接口 | 统一银行协议、请求与结果类型、能力声明、连接配置和注册入口 | 新增连接器时可以实现既定协议，无须改动任务与授权内核 |
| 模型接口 | API 地址、API key 引用、模型名称、协议类型，以及统一调用与输出契约 | 后续模型接入使用同一配置和数据结构，保留现有 DeepSeek 配置兼容路径 |
| 插件接口 | 插件清单、配置与权限模式、注册及生命周期约定、调用与结果契约 | 自定义扩展可以按文档编写并接受契约校验，尚未实现的运行能力明确标注 |

本期不包含银行账户申请、证书配置、真实账户查询、付款联调、各厂商 SDK 接入、真实 API 压测或生产验证。插件安装器、自动更新、商店和第三方代码隔离运行平台也不纳入本期。

## 银行接口准备

复用现有 `Bank` 协议和 `packages/bank-contracts/`，补充类型与能力描述。模拟银行仍在独立目录运行，任务服务继续经既有认证接口访问它。

| 接口组 | 设计内容 |
|---|---|
| 能力声明 | 声明账户、明细、转账、卡片、理财、查询、幂等和证据等可用能力 |
| 业务查询 | 账户、余额、明细、收款人及已声明支持的产品或服务查询 |
| 操作准备 | 参数校验、预览、费用或额外用户确认要求的标准结果 |
| 操作执行 | 接收稳定操作编号、主体、动作和已校验参数 |
| 结果核实 | 按原操作身份查询，区分处理中、成功、失败、未知及需要用户处理 |
| 证据返回 | 返回来源、业务记录引用、数据和验证时间，供控制内核核实 |

统一定义 `BankConnection`、`BankCapabilities`、`BankOperationResult` 和 `BankEvidence` 等数据结构，具体名称以实施时的契约评审为准。连接配置至少包含连接编号、提供方标识、环境、接口版本、配置版本和凭据引用。

金额继续使用最小货币单位的整数，并显式记录币种。操作、授权和证据保留关联；连接或关键参数变化时重新匹配授权。所有银行读写仍经过控制边界，未知结果先查询原操作。

未配置的提供方返回明确的未配置错误；未声明的能力返回不支持。模拟器的查询栅栏等专属能力单独声明，不作为通用接口的默认保证。接口声明和配置填写均不能证明已连接真实银行。

本期只预留不同认证材料的引用位置，不实现任何银行的签名、验签、加密、字段映射或原始响应码转换。未来如需适配，由独立连接器完成。

## 模型接口准备

模型配置采用“API 地址＋API key＋模型名称”，另行记录协议类型。预置配置可以减少填写项目，但不把某个厂商或模型名称固化到通用接口中。

| 配置字段 | 用途 |
|---|---|
| `connection_ref`、`owner_ref` | 连接身份与用户归属 |
| `base_url`、`protocol` | 服务地址及调用协议 |
| `model_id` | 明确选择的模型 |
| `credential_ref` | 服务端密钥引用，读取接口只返回掩码或配置状态 |
| `capabilities` | 工具调用、结构化输出、流式和思考等能力的声明与验证状态 |
| `timeout`、`concurrency`、`budget` | 超时、并发、请求和 Token 预算 |
| `connection_version` | 配置版本与调用追溯 |

定义统一的完整响应和流式事件接口，以及消息、工具模式、工具调用、结束原因、用量和错误类型。接口只表达通用语义，特殊能力通过明确的扩展字段描述；未实现的协议返回不支持。

`ModelConnectionRepository` 已预留创建、按用户查询、版本更新和停用协议，尚无持久化实现。HTTP 入口 `/v1/integrations/model-connections/validate` 只检查本地格式和约束，不发起真实推理，也不保存或激活连接。

保留现有 DeepSeek 环境变量及自定义计划网关的兼容说明。自定义计划网关与通用模型消息协议分别标识，不能把两种请求格式混用。本期不扩展新的厂商 SDK，也不宣称所有国内模型均已兼容。

API key 按用户和连接隔离，调用时由服务端解析引用。插件、日志、任务报告和模型上下文不获得明文。地址、密钥和连接版本绑定，避免配置变更后把原密钥发送给其他服务。

## 插件接口准备

预留工具、模型提供方、银行连接器、报表和任务模板等扩展类型。实际功能实现可以以后独立增加。

| 契约 | 需要固定的内容 |
|---|---|
| 插件清单 | 标识、版本、宿主接口兼容范围、扩展类型和入口描述 |
| 配置模式 | 必填项、数据类型、默认值及凭据引用字段 |
| 工具描述 | 命名空间、输入输出模式、业务类别及所申请权限 |
| 注册与生命周期 | 注册、兼容性检查、启用、停用和卸载的接口约定 |
| 调用上下文 | 调用编号、主体、任务与操作引用、插件版本、受限上下文和截止时间 |
| 执行结果 | 结构化状态、数据、来源、错误及证据引用 |

插件权限声明只是申请，实际授权仍由服务端记录和校验。插件不能覆盖核心工具名，不能自行签发授权，也不能通过把写操作标为只读来绕过控制。

本期提供契约、注册扩展点及开发说明，不执行用户提供的任意代码。生命周期接口的约定也不等于已实现包安装、远程下载或安全沙箱。未来若引入用户代码运行，需单独实现进程、文件、网络和资源隔离。

## 目录与兼容策略

| 位置 | 本期处理方式 |
|---|---|
| `packages/bank-contracts/` | 扩展现有中立类型与能力契约 |
| `src/finguard/backend/bank.py` | 保留现有协议和客户端，准备连接器注册边界 |
| `services/bank-simulator/` | 继续承担模拟业务实现与相关回归验证 |
| `src/finguard/integrations/models/` | 统一模型契约、配置类型及受信工厂注册入口 |
| `packages/plugin-contracts/` | 独立插件清单、配置模式及调用契约 |
| `src/finguard/plugins/` | 受控元数据注册和生命周期扩展点，无代码运行能力 |

新目录随实际代码引入，不提前创建空目录。现有任务、计划、授权、操作和证据的行为作为兼容基线。新契约采用显式版本，旧操作恢复时不重新解释已绑定的参数或执行环境。

## 实施步骤与验收

| 阶段 | 交付物 | 验收标准 |
|---|---|---|
| I0：接口清单 | 三类接口的职责、字段、版本及错误约定 | 分清已有实现、待实现协议和未来适配职责 |
| I1：银行契约 | 类型、能力声明、连接配置与注册入口 | 现有模拟实现能保持兼容；未配置或不支持时明确失败 |
| I2：模型契约 | 地址、密钥引用、模型、统一消息与响应结构 | 配置可校验；密钥不回显；保留现有 DeepSeek 兼容路径 |
| I3：插件契约 | 清单、配置模式、调用上下文与生命周期约定 | 可校验示例声明，拒绝命名冲突、版本不兼容及非法权限声明 |
| I4：契约验收 | 接口文档、开发示例和自动化检查 | 不依赖真实银行或新增模型密钥即可验证；现有业务回归保持通过 |

I0 至 I4 的接口准备已完成。银行只注册现有模拟提供方；通用模型注册目录初始为空。插件注册和生命周期仅管理元数据，执行入口明确返回未实现。全程不以真实服务接入为验收前提，不要求银行账号、证书或新的模型密钥。

测试使用现有模拟银行和仅用于测试的替身，验证数据格式、错误处理、权限边界与兼容性。替身不作为业务实现，也不能用固定成功值冒充付款或服务能力。

现有 [216 项测试和隔离验收](service-isolation.md)是历史基线。本轮新增契约及 HTTP 校验测试，验证结果与复现命令见[扩展接口说明](extension-interfaces.md)。真实适配、连接持久化、插件运行平台和前端仍需独立开发与验收。
