# 开发路线

各阶段按依赖推进。当前已完成准备阶段、开发基础和领域契约。P1 的模拟银行与存储仍待实现。

具体执行顺序、编码任务和里程碑见[实施步骤](implementation-plan.md)。当前完成步骤 1 和步骤 2，下一批进入步骤 3。

## 阶段与验收

| 阶段 | 实施内容 | 验收条件 | 状态 |
|---|---|---|---|
| P0：项目准备 | 原文归档、架构整理、开发约定、模拟场景 | 资料完整，当前能力与计划清楚分开 | 已完成 |
| P1：领域与工具契约 | 最小技术栈、核心对象、状态迁移、工具注册表、模拟账本与适配器 | 金额、资源归属、参数和契约测试通过 | 进行中；模拟账本与适配器待实现 |
| P2：可靠执行内核 | 操作持久化、稳定编号、幂等、查询核实、重启恢复 | 重复请求及响应丢失不会重复记账 | 待实现 |
| P3：授权与策略控制 | 单次授权、权限、提交前复检、限额和并发控制 | 无有效授权的写入被阻断，竞争支出不突破约束 | 待实现 |
| P4：任务编排 | 计划版本、依赖、调度、停止、部分完成和证据验证 | 固定转账计划形成可回放的完整执行闭环 | 待实现 |
| P5：动态规划与专业角色 | 意图解析、计划编译、审查、澄清、局部重规划 | 新组合任务经过校验，已完成操作不重复执行 | 待实现 |
| P6：调试与评估 | 轨迹查看、固定输出与重新调用模型回放、故障注入 | 可复现失败并定位层级，分别报告两类成功指标 | 待实现 |
| P7：离线优化 | 失败归因、改进候选、隔离评估、回归、发布与回退 | 优化可比较、可回退，控制边界持续成立 | 待实现 |

P2 可以验证纯模拟环境下的执行协议。完整业务写入入口需在 P3 完成授权控制后开放。

## 首个开发切片

先实现“向已确认收款人转 300 元，转后至少保留 1,000 元”的模拟场景。默认费用为 0 元，仅用于验证首个切片。

1. 确定语言、依赖管理和本地测试方式。
2. 定义核心对象、状态迁移和工具元数据。
3. 建立模拟账户、账本、状态查询和故障脚本契约。
4. 实现并测试执行内核，再接入授权控制。
5. 用固定计划完成提交、核实、验证和报告。
6. 覆盖缺少授权、余额变化、重复提交、响应丢失和重启恢复。
7. 在控制与执行闭环可验证后引入模型规划。

界面、部署和真实服务接入按后续需求安排。账单、理财、卡片、订阅和跨服务任务沿用核心控制边界，并分别定义业务语义。

## 每阶段交付要求

- 明确输入、输出、前置条件和失败语义。
- 提供与变更相称的验证，保留可复现的模拟数据。
- 更新项目当前状态、选型记录和相关契约说明。
- 按实际执行结果报告验证范围；未覆盖的性质继续标为待验证。
