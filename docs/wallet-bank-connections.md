# 卡包中的银行选择与导入

日期：2026 年 10 月 29 日。卡包已实现银行下拉选择、连接、读取资产、选择导入、同步状态和移除连接。当前接通的是独立模拟银行；尚未接入任何真实银行或外部银行 MCP。

## 操作流程

1. 在“卡包”点击“添加银行卡”。
2. 下拉选择服务端目录中已经配置的银行。
3. 点击“连接所选银行”，服务端按银行编号选择受信适配器，实际读取当前主体的账户和卡片。
4. 勾选银行返回的资产，点击“导入所选资产”。账户与银行卡分别标明，不补造银行卡号。
5. 已导入资产显示来源银行、类型、资产引用、状态和最近同步时间。刷新后重新登录仍可读取。
6. “添加账户或卡片”可继续导入同一连接的其他资产；“同步状态”重新读取银行；“移除连接”移除卡包展示，不销卡、不关闭银行账户，也不撤销或停止已有业务任务。

模拟银行使用当前已经认证的模拟主体和服务端服务密钥。它没有独立的银行登录页面，也不要求用户输入真实银行卡号、银行密码或 API 密钥。真实银行的 OAuth、回调、授权期限和受保护凭据存储尚未实现，不能把模拟连接当作真实银行授权。

原有模拟卡片操作与订阅管理继续保留。卡包导入是应用内的资产关联，不新增付款权限；锁卡、转账等操作仍经原任务预览与授权流程。

## 服务端目录与绑定

`EnrollmentBank` 将银行编号绑定到受信适配器。目录只按服务端实际配置返回，不接受客户端指定任意提供方、服务地址或资产归属。当前仅在系统配置为 `simulated-bank / simulation` 时注册“FinGuard 模拟银行”；其他配置返回空目录，不自动回退到模拟银行。

当前实现限定为模拟连接。以后接真实银行时，需要先扩展正式授权生命周期与连接器注册，再把对应机构加入目录。不能只改银行名称或将任意 MCP URL 写入下拉列表。

数据库迁移 `005-wallet.sql` 保存用户、银行、连接与导入资产关联。业务数据继续来自独立银行服务。连接请求按用户与请求编号幂等；同一主体和银行只允许一个有效连接；资产按连接、类型及银行资源引用去重。移除后可以通过新请求重新连接，原请求不能恢复已移除连接。

## 接口

| 接口 | 用途 |
|---|---|
| `GET /v1/wallet/banks` | 读取已配置银行及可用能力 |
| `GET /v1/wallet` | 读取当前主体的连接和导入资产 |
| `POST /v1/wallet/connections` | 按 `bank_ref` 和 `request_ref` 连接 |
| `GET /v1/wallet/connections/{connection_ref}/assets` | 实际读取该连接的可导入资源 |
| `POST /v1/wallet/connections/{connection_ref}/import` | 按 `asset_refs` 导入服务端校验后的资源 |
| `POST /v1/wallet/connections/{connection_ref}/sync` | 更新已导入资产的状态和同步时间 |
| `POST /v1/wallet/connections/{connection_ref}/disconnect` | 移除应用内连接 |

读取要求 `accounts.read` 和 `services.read`，修改额外要求 `tasks.write`。服务端逐次检查主体归属，不采信客户端自报的用户编号。导入前重新读取资源，包含无效资源的整批导入会被拒绝；同步中不再返回的资产标记为不可用。银行读取失败不会创建假连接，也不会更新为同步成功。

连接响应不明时，界面复用原请求核对，同时刷新连接列表。重新打开后可从已有连接继续导入。单个连接的导入上限为每次选择 100 项；不传输完整卡号、密码或银行服务密钥。

## 验证与剩余工作

前端组件检查覆盖银行选择与请求绑定、勾选资产和导入。后端检查覆盖重复连接、重复导入、同步与移除、未知银行、任意地址注入、跨主体访问、读写权限及银行失败。浏览器使用独立模拟服务完成完整流程，实际结果见[前端验收](frontend-validation.md)。

真实银行接入还需要选定银行及提供方、取得可用应用凭据、实现正式授权和回调，并将查询与业务执行绑定到相同的连接。当前导入元数据不提供通用多银行付款路由。桌面 EXE 尚未重新构建。
