# 设计决策与待定事项

记录日期：2026 年 10 月 26 日。依据为用户提供的[原始框架](sources/project-framework.txt)。

## 已确定的设计原则

| 原则 | 理由 |
|---|---|
| 五个业务对象显式建模 | 对话记录不足以表达真实业务状态 |
| 认知、控制和执行分开 | 模型建议不能替代确定性规则与业务验证 |
| 任务和操作分开持久化 | 支持部分完成、未知结果和故障恢复 |
| 授权匹配操作及关键参数 | 防止计划变更后继续使用不适用的授权 |
| 未知状态先核实 | 超时不能证明操作未生效 |
| 先建立模拟执行闭环 | 提供可重复的业务状态和故障条件 |
| 离线评估改进策略 | 让规划优化可比较、可审核、可回退 |

这些原则是实现要求，尚未形成已验证的软件保证。

## 待定工程选型

| 项目 | 确定时机 | 需要回答的问题 |
|---|---|---|
| 编程语言、运行时与依赖管理 | P1 开始时 | 开发环境、维护成本、测试支持 |
| 数据库及一致性方案 | P1～P3 | 操作持久化、并发扣款、授权消费和审计 |
| 服务接口与身份认证 | 建立服务入口前 | 主体识别、数据隔离和授权来源 |
| 工作流框架与任务队列 | P4 | 恢复语义、调度、异步核实和部署需求 |
| 模型服务及角色路由 | P5 | 结构化输出、成本、数据范围和评估 |
| 界面形式与轨迹查看方式 | 出现交互需求时 | 授权展示、任务停止和状态核实 |
| 真实业务适配器 | 单独接入阶段 | 幂等、查询、回调、费用和业务授权机制 |
| 部署方式与许可证 | 需要交付或发布前 | 运行环境、运维要求和分发授权 |

原框架提到 LangGraph 的恢复语义，本文将其作为候选框架的注意事项，不视为选型结论。
