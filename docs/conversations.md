# 对话与任务分流

日期：2026 年 10 月 29 日。前端支持普通 AI 对话、目标澄清和任务执行。对话消息与业务任务分别保存；不是每条消息都会创建任务。桌面候选已于同日重新构建，实际 EXE 检查见[发布验收](release-preparation-validation.md)。

## 导航与任务分类

侧栏顶部为“新对话”。点击“任务”只展开或收起菜单，不离开当前聊天。菜单下列出待完成、已完成、已结束和全部任务；点击分类查看列表，再打开具体任务。

待完成包含规划、执行、等待确认、需要补充及待核实状态。已完成要求任务完成、当前计划操作全部成功且各有对应业务证据；单有 `COMPLETED` 标记不足以进入已完成分类。已结束对应终止任务。数量按当前主体的全部服务端记录计算，列表按引用分页，每页 25 条。

对话历史单独收起管理。一个对话可以没有任务，也可以关联多个任务。聊天和待澄清目标不计入任务分类。

## 消息处理

| 消息 | 行为 | 建立任务 |
|---|---|---|
| 你好、介绍一下自己 | 普通模型回复 | 否 |
| 转账需要注意什么 | 解释与交流，不查询银行 | 否 |
| 给小王转账 | 在对话中询问缺失信息 | 否 |
| 300 元，接续缺少金额的单笔转账 | 补全目标，校验参数，再登记 | 参数完整后建立 |
| 查询当前余额、查看上个月账单 | 创建查询任务并自动推进 | 是 |
| 给小王转 300 元，至少保留 1000 元 | 创建计划并显示确认卡 | 是，资金操作需授权 |
| 改成 200 元，接续当前业务 | 修订原任务未提交的转账，保留其他事实和约束 | 不重复创建 |

意图识别采用保守规则及已配置模型。解释、假设、风险讨论等不会仅因提及转账而调用银行。模型返回的意图只用于候选路由，任务仍通过服务端参数、权限、业务预览及授权检查。识别不确定时先澄清；参数不足时保存待澄清目标，不创建空任务。

可以回复单笔缺失金额，或以“完整目标：……”重述全部目标。普通聊天不会被上一笔待确认业务强制转为补全流程；聊天后出现“改成 200 元”等歧义指令时，要求明确目标，避免改写错误任务。复杂修订继续使用完整计划编辑器。

聊天中的“好”“可以”按上下文处理。接续操作卡片时仍提示明确确认，不签发付款授权；正常聊天中则继续交给模型理解。已完成、已提交或待核实操作继续保留为事实。

## 普通 AI 对话

普通聊天使用 DeepSeek 对话客户端，支持最近对话上下文和真实流式响应。普通对话通道没有银行工具，也不向模型注入工具查询结果。AI 回复作为文本显示，业务状态和凭证仍由任务组件展示。

`FINGUARD_CHAT_PROVIDER` 支持：

- `auto`：默认值，任务模型为 `deepseek` 时同时启用普通聊天；其他任务模型不自动启用聊天。
- `deepseek`：单独启用 DeepSeek 聊天，任务规划器仍可保持 `deterministic`。
- `disabled`：关闭普通聊天，仍可识别支持的明确业务请求。

在受忽略的服务端 `.env` 或进程环境中配置 `FINGUARD_CHAT_PROVIDER=deepseek` 和 `FINGUARD_DEEPSEEK_API_KEY`，重启后端生效。可复用已有密钥配置；密钥不进入前端。当前设置页的连接格式校验不保存或启用模型。其他聊天协议适配与桌面模型密钥管理尚未实现。

模型未配置、回复中断或返回无效格式时明确显示状态，不使用固定文案冒充模型成功回复。可以重试同一条 AI 消息，不重复创建任务。AI 回复有上下文、并发、时限和输出长度限制；不保存隐藏推理。

## 接口与恢复

| 接口 | 用途 |
|---|---|
| `GET /v1/conversations?before=...` | 按主体分页读取对话 |
| `GET /v1/conversations/{conversation_ref}` | 读取消息、可选任务引用、回复及处理状态 |
| `POST /v1/conversations/{conversation_ref}/messages` | 保存消息并进行意图分流 |
| `GET /v1/chat/status` | 普通聊天配置状态，不返回凭据 |
| `GET /v1/task-groups/counts` | 全量任务分类数量 |
| `GET /v1/task-groups/{pending,completed,ended,all}?before=...` | 分类列表分页 |

消息请求保留 `message_ref`、`content`、`expected_sequence`。服务端检查主体与消息顺序，保存处理意图后执行。消息新增 `kind` 与可选 `error_code`；`task_ref` 可以为空。待澄清目标仍在内部消息载荷中，不进入任务表。

普通聊天由后台工作处理，服务端按真实流式片段更新回复，前端每秒读取未完成消息。它不是浏览器直接连接模型，也不通过逐字动画模拟流式。中断后可复用原消息重试；进程重启后，待处理消息可由恢复按钮重新启动。回复失败会结束本次等待，允许继续聊天或重试。

新任务使用由对话和消息派生的稳定创建编号。修订任务保存目标版本与步骤，恢复时核对状态，防止重复替换。业务操作继续沿用原授权、幂等和证据边界。查询自动推进，资金操作在匹配授权范围内执行。

每个对话最多 100 条用户消息。主体隔离、有限脱敏和跨窗口顺序冲突检查继续有效。对话删除、重命名、搜索及跨设备未读尚未实现。

## 验证

前端检查覆盖任务菜单展开与服务端数量、分类导航、丢失消息恢复等。后端覆盖普通聊天不建任务、不读取银行、缺失模型、上下文回复、重试、待澄清目标补全、证据缺失时重新分类，以及真实 SSE 响应格式与中断处理。测试使用模型替身，不调用付费模型。

实际检查结果及浏览器范围见[前端验收](frontend-validation.md)。隔离模拟服务通过 `FINGUARD_CHAT_PROVIDER=disabled` 明确关闭普通模型调用。
