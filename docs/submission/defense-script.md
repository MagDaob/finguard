# FinGuard 答辩讲稿

适用版本：0.3.0。共 12 页，建议汇报 8 分 50 秒，预留 1 分 10 秒。时间包含翻页与界面讲解。演示采用虚构数据，不涉及真实资金交易。PPTX 备注同步保留逐页讲稿与来源。

## 第 1 页：FinGuard（25 秒）

各位评委好，我们是 Finguard 队。FinGuard 是面向金融任务的可恢复智能体工作台。用户提出目标，系统生成可检查的计划，取得参数明确的授权，再用业务证据核实结果。当前提供模拟工作台和 Windows 便携版。真实模型参与候选规划，系统没有接入真实银行。

## 第 2 页：一笔带约束的转账（40 秒）

用户有 1,500 元，要求给小王转 300 元，并至少保留 1,000 元。系统需要完整保留对象、金额和余额约束。即使模型输出合理计划，没有确认也不能扣款。确认后仍须复检权限和资金条件。最终展示 1,200 元余额，并关联银行记录、流水与余额证据。工具返回成功，不足以证明目标完成。

## 第 3 页：系统架构（55 秒）

前端展示目标、预览和证据。理解与规划层提交候选，执行内核负责权限、参数和业务规则。应用数据库保存任务、计划、授权、操作与证据。独立模拟银行保存账户、账本和权威结果。双方通过认证 HTTP 通信，源码、进程、环境、数据库和账号均已分开。模型没有业务放行权限，应用也不直接修改银行数据库。两次提交之间发生故障，通过稳定操作编号恢复核实。

## 第 4 页：有界 Agent 规划（45 秒）

Agent 面对已经验证的结构化目标。简单任务采用单次紧凑候选；更多目标、到账条件或思考模式进入循环。循环只开放按需查询和提交候选两个规划工具。默认最多四轮，并限制调用数、并发和时限。编译器检查全部目标、完整参数和依赖。模型不能增加付款、改变金额或删去到账条件。错误候选收到明确反馈，重复调用或超限则停止。

## 第 5 页：权限与业务授权（50 秒）

访问令牌确定主体、权限和资源归属，读操作也要检查。写操作还需单次参数确认或受限转账委托。确认绑定操作编号、参数摘要和期限；委托限制账户、收款人、单笔额度、累计预算与频次。提交前重新检查，参数变化后原授权失效。超过默认高金额门槛时需要额外身份验证。当前验证服务未接入，所以阻止执行，模型不能声明验证成功。

## 第 6 页：响应丢失后的恢复（45 秒）

假设银行已扣款，但响应丢失。直接重付可能重复扣款。FinGuard 调用银行前先保存提交意图，故障后保持结果未知，并查询原操作。项目重启仍使用同一编号，取得权威证据后再报告完成。停止只取消尚未提交的节点，已提交的操作继续核实。模拟银行支持幂等和查询栅栏；真实银行未必提供相同保证，接入时须重新验证合同语义。

## 第 7 页：实际工作台（45 秒）

这是实际工作台截图，姓名和账户均为演示数据。工作台展示任务、计划、确认与凭证，业务页可以查看账单、产品和服务。只有当前操作完成、核实标记成立且存在关联证据时，界面才展示完成。未知状态继续查询原任务，没有重新付款按钮。桌面版独立启动应用、模拟银行和数据库，默认使用确定性规划器，演示不产生付费模型调用。

## 第 8 页：短计划的模型开销（55 秒）

同一组短计划中，全量基线、按需循环与自适应路径的输入 Token 分别为 3,480、5,958 和 1,203。循环每例用了两轮，增加了短任务开销，因此加入自动选择。自适应路径相对全量基线减少约 65.4% 的输入 Token，模型累计等待时间基本相同。样本只有三个情景，顺序未随机化，循环有缓存命中。结果不能推广为所有任务的性能结论。

## 第 9 页：真实 API 与业务情景（45 秒）

DeepSeek 专项共执行三十次真实请求。并发一、二、四时，短响应吞吐分别约为每秒一点六五、三点八四和五点四九次。十六个吞吐请求全部成功。这是小样本初步验证，不是服务商最大容量测试。业务测试覆盖有效授权、等待授权和响应丢失恢复。每个策略正确处理三种情景；等待授权不算完成，所以合法任务完成率为二分之二。

## 第 10 页：验证依据（45 秒）

后端测试覆盖权限、并发、恢复、账本和证据；前端组件与浏览器联调覆盖会话、确认和未知状态。发布脚本从实际 ZIP 解压 EXE，在独立中文目录中检查转账、幂等、单实例、重启与退出。材料标明各报告的日期与提交，避免混合不同阶段的测试数。现有结果证明覆盖情景可运行，不能视为生产安全或完整兼容性认证。

## 第 11 页：可扩展接口（50 秒）

银行、模型和插件都有准备好的契约。银行声明能力，模型使用地址、协议和密钥引用，插件声明工具、模式与权限。当前接口只做本地校验，不保存或激活新连接。通用模型网络客户端和第三方插件宿主尚未实现。插件元数据启用也不会获得业务权限。后续可以按需求接入服务，并继续经过既有授权、幂等和证据控制。

## 第 12 页：当前边界与下一步（30 秒）

当前成果是可运行的模拟金融工作台，以及可追溯、可恢复的执行内核。下一阶段优先完成正式身份、真实额外验证、网络防护和代表性评估，再讨论真实银行接入。源码已公开，采用 Apache-2.0。技术文档、安全自评和源码部署包提供复核入口。谢谢各位，欢迎提问。

## 备选问答

**模型能直接付款吗？** 不能。模型提交候选，业务服务校验权限与授权；缺少有效授权时等待确认。

**是否已接入真实银行？** 没有。目前只有独立模拟银行及真实接入所需的契约准备。

**为什么不让全部任务循环？** 短计划实测显示两轮循环增加开销。auto 按任务条件选路径，复杂任务效果仍待评估。

**是否绝对不会重复付款？** 当前模拟器和覆盖场景通过检查。真实下游的幂等与权威查询须重新验证，不能作绝对保证。

**安全还缺什么？** 正式身份、实际额外验证、限流与出口隔离、真实银行合同测试、恢复演练和第三方测试。
