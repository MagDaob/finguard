# FinGuard 安全自评报告

权限分级实现说明与已知风险清单

队伍：Finguard

适用版本：0.3.0（模拟业务预览版）

评估日期：2026 年 10 月 28 日

材料基线：仓库提交 d1dbc8d

仓库：https://github.com/MagDaob/finguard

本报告为项目组基于源码、测试和已有验收记录的内部自评。它不是第三方渗透测试、合规审计或银行安全认证。范围覆盖应用、Agent、独立模拟银行、前端及 Windows 外壳。

自评结论：当前适合虚构数据的本机演示与开发验收。已有权限、授权、幂等、核实和证据控制；正式身份、生产网络防护、真实银行合同验证和系统化安全测试仍有缺口。

## 资产、攻击面与信任边界

| 资产 | 位置或通道 | 主要威胁 |
|---|---|---|
| 访问令牌与主体 | 应用内存、令牌摘要表 | 盗用会话、越权读取或写入 |
| 授权与委托预算 | 应用数据库 | 篡改参数、并发超支、过期重放 |
| 操作与业务证据 | 双方数据库、认证 HTTP | 重复付款、伪造成功、证据错绑 |
| 模型与服务密钥 | 本机配置、进程环境 | 外泄、误转发、跨服务读取 |
| 模拟账户与账本 | 独立银行数据库 | 未授权写入、账本不一致 |
| 用户输入及导出 | 页面、任务文字、报告 | 指令注入、秘密或个人数据外泄 |

模型、用户输入、插件声明及回调内容均不能自行产生权限。确定性服务解析主体，验证访问范围与资源归属，再匹配业务授权。读取也受该边界控制。

模拟银行信任服务密钥，接受应用传递的业务主体。这是内部服务信任边界：如果应用控制面或服务密钥失陷，现有设计不能等同于银行侧的独立客户签名。真实银行须建立其自身授权与验签机制。

Windows 同一操作系统用户拥有本机模拟数据。DPAPI 保护配置的静态保存，不能阻止已取得该用户权限的恶意进程。管理员、被攻陷的操作系统和数据库超级用户不在当前隔离保证之内。

外部模型会接收经过校验的目标及约束，其中可能包含业务引用、金额和相关信息。未发送访问令牌、授权记录和数据库凭据，不等于实现完整数据匿名化。

## 权限分级与业务确认

| 层级 | 实际权限或机制 | 可执行范围与限制 |
|---|---|---|
| 未认证 | 存活、就绪等公开入口 | 不能读取用户业务或创建任务 |
| 业务读取 | accounts.read、transactions.read、services.read、products.read、tasks.read | 按接口和动作检查权限与归属 |
| 任务管理 | tasks.write | 创建、推进、停止、重规划；不替代业务授权 |
| 操作确认 | approvals.write | 确认自己的操作或建立受限委托；仍需具体业务写权限 |
| 业务写入 | transfers.write、services.write、investments.write | 通过授权和业务规则后提交对应动作 |
| 运营评估 | evaluation.manage、simulation.manage | 需受信签发；HTTP 评估入口默认关闭 |

上述为权限范围组合，不是已经接入的企业角色系统。普通演示令牌可包含多项用户权限；管理员令牌包含普通权限和运营权限。生产角色分配与职责分离需要另行设计。

单次授权绑定主体、操作编号、规范参数摘要、期限及状态。创建时检查预览摘要，提交时重新检查权限与期限。参数改变后，原授权不能适用于新操作。

受限委托仅支持转账，约束源账户、收款人白名单、单笔上限、累计额度、频次和期限，并支持撤销。行锁与原子预算更新协调并发。未知结果保留预算，明确失败释放金额占用，尝试频次保留。

高金额验证默认在总扣款超过 1,000 元时触发。当前没有实际验证提供方，因此返回 STEP_UP_REQUIRED 并阻止新提交；金额等于门槛时按普通确认处理。该门槛是模拟开发策略。

## 控制措施与证据映射

| 风险 | 当前控制 | 源码或检查入口 |
|---|---|---|
| 越权及令牌重放 | 高熵令牌、摘要保存、到期撤销、执行复检、资源归属 | security.py；test_api.py、test_controls.py |
| 模型扩大目标 | 严格模式、完整目标对照、参数与依赖不可变 | planning.py；test_planning.py、test_deepseek.py |
| 重复扣款 | 稳定操作编号、意图持久化、唯一流水、未知先查询 | service.py；test_bank.py、test_process_recovery.py |
| 授权并发超支 | 授权行锁、委托预算原子消费、账户锁 | authorization.py；test_controls.py、test_bank.py |
| 伪造回调 | HMAC-SHA256、300 秒时间窗、事件去重、重新查询 | service.py callback；test_api.py |
| 业务成功误报 | 权威记录、流水、金额及余额证据核验 | service.py、bank.py；test_service.py |
| 服务混用凭据 | 独立配置、环境、数据库和普通账号 | docs/service-isolation.md；容器隔离检查 |
| 前端会话串用 | 内存令牌、主体缓存隔离、401 清理、延迟响应隔离 | frontend/src/；前端组件检查 |

请求体默认上限为 1 MiB，分页及计划节点数有边界。DeepSeek 规划有轮次、调用数、并发和时间限制。这些控制减小资源滥用范围，不能替代按身份限流和生产容量防护。

回调成功声明不会直接落为业务成功。即使签名有效，系统仍查询银行权威状态。未配置回调密钥时入口关闭。

正式服务与评估流程分离。离线回放创建随机命名空间；候选策略需对照评估及显式审核。提示词发布不修改权限、授权、限额或账本。具有数据库管理权限的本机操作者仍属于受信边界。

## 数据、密钥与扩展安全

开发凭据保存在被忽略的配置或环境变量中。公开配置只保留替换说明。DeepSeek 密钥固定发送到官方接口，不跟随重定向，不自动转发到自定义网关。

桌面配置使用 Windows DPAPI 绑定当前用户。应用与模拟银行使用不同数据库账号；服务只监听本机地址。外壳通过启动挑战校验服务身份，桥接只接受本机页面；数据目录与安装目录分开。

任务文字和导出递归应用已知秘密、银行卡号及手机号的有限脱敏规则。原始请求摘要继续用于重试一致性。历史数据库原话不自动回写；导出标记明确不保证完整检测。隐藏推理仅在同次模型调用链内透传，不记录到轨迹或评估报告。

| 扩展面 | 当前限制 | 仍需补充 |
|---|---|---|
| 模型地址 | 禁止内嵌凭据、查询与片段；本机 HTTP 须显式启用 | 出口白名单、DNS 重绑定及私网阻断 |
| 密钥引用 | 校验 env: 或 secret:，拒绝 HTTP 明文 api_key | 可靠密钥托管、轮换与审计 |
| 插件模式 | 限制大小、深度和节点；拒绝引用及正则模式 | 实际执行隔离、资源配额和授权代理 |
| 插件状态 | 仅元数据，invoke 明确返回不可用 | 独立进程、文件网络能力及供应链审查 |

源码材料只收录受版本管理的文件，并在交付前检查路径与已知本机秘密。运行数据库、令牌、日志和开发 .env 不进入压缩包。文件清单与 SHA-256 用于核对完整性，不能替代来源签名。

Apache-2.0 仅覆盖项目自有代码；第三方依赖保留各自许可。Windows 便携包当前未签名，首次系统提示和传播来源需由使用者核对。

## 已知风险清单与整改顺序

以下等级为项目组按潜在影响与当前缺口作出的内部排序，未采用第三方认证评分。优先级面向未来真实数据或外网部署；当前演示必须使用虚构数据。

| 编号 / 等级 | 已知风险及影响 | 当前处置 / 后续措施 |
|---|---|---|
| R01 高 | 正式登录、续期与真实额外验证缺失，无法支撑生产身份链 | 保留本机演示；接入身份提供方并验证撤销和升级认证 |
| R02 高 | 真实银行尚未适配，不能继承模拟幂等、查询栅栏和授权保证 | 只用模拟器；真实接入前做合同测试与对账演练 |
| R03 高 | 应用控制面及服务密钥可代表内部业务主体，失陷影响整个模拟服务 | 本机监听和独立凭据；补充下游独立授权及密钥轮换 |
| R04 高 | 外网 TLS、按主体限流及网络出口隔离不完整 | 暂不作为公网金融服务；部署前实现网关、出口策略和容量验证 |
| R05 中 | 脱敏有限，目标字段或历史数据可能包含敏感信息 | 使用虚构数据；导出复查，增加数据分类与最小发送策略 |
| R06 中 | 桌面未签名，完整新机覆盖和升级迁移尚未验证 | 保留校验清单；签名、干净虚拟机与迁移验收 |
| R07 中 | 同一 Windows 用户可读取运行进程和数据库，DPAPI 不隔离恶意同用户程序 | 限定受信本机；评估系统权限和受保护密钥服务 |
| R08 中 | 备份恢复、集中监控及告警尚无生产演练 | 保留数据库工具指导；演练双库一致恢复和未知交易核实 |
| R09 中 | 插件声明通过不证明代码安全，未来执行会增加攻击面 | 当前不执行；建立隔离宿主、最小权限和资源配额 |
| R10 中 | 自动测试与样本有限，不能排除所有并发、注入和依赖风险 | 增加性质测试、代表性对抗集、依赖审计及第三方测试 |

R01 至 R04 是真实数据或公网部署前的阻断项。风险清单不表示其他项目已完全安全，也不把模拟验收结果当作真实资金场景的上线依据。

## 验证范围与自评结论

本报告整理已有验证与当前源码。材料编制期间不重新调用付费模型，不测试真实银行，不对外部系统开展扫描或渗透测试。

| 已有证据 | 结果 | 解释边界 |
|---|---|---|
| 后端故障与权限回归 | 覆盖授权、并发、恢复、主体和证据 | 详见对应提交，不表示穷尽证明 |
| 真实模型专项 | 30 次调用；短计划情景正确处理 | 业务仍是模拟，不代表开放理解质量 |
| 前端专项 | 会话、授权复检、未知状态及整数金额检查 | 正式身份与部分运营入口待验收 |
| 发布准备 | 26 项规则检查；EXE 转账、幂等、重启及退出自检 | 预览候选，未签名，兼容性覆盖有限 |
| 远端验证 | 47a7195 的 11 项常规任务及 1 项 Windows 构建通过 | 属于该提交的历史工程证据 |

当前安全设计把模型候选与业务放行分开，并保持任务、计划、授权、操作和证据的显式关联。未知结果继续核实，证据不足不报告成功。上述机制适用于当前已验证的模拟服务边界。

对真实金融服务的自评结论为“尚未具备上线条件”。在引入真实数据或公网入口前，需完成 R01 至 R04 整改，并重新验收身份、资金操作、网络边界、恢复及监控。
